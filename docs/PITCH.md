## Slide 2 — How it works (RFQ example) + why

### How it works — RFQ as the example

**Input:** Solicitation folder (RFQ + PWS + wage tables + Q&A + justifications…).

| Step | What happens |
|---|---|
| Triage | Real RFQ kept; wage tables / boilerplate marked not relevant |
| Extract | Your fields + confidence; blanks get a reason |
| Review | Original next to fields; click a value → see source on the page |
| Export | Approved rows → Excel |
| Next (optional) | Procurement task → draft vendor emails → quotes → delivery → invoice |

Other document types (invoices, POs, CVs, leases, claims, shipping, vehicles, contracts) use the **same pipeline** — different fields and “in scope” rules only.

### Why it matters

- Private by default — local model; documents stay on your hardware  
- Built for messy inputs — PDFs, scans, Word, Excel  
- Human in the loop — confidence scores; approve with a keystroke  
- One app, many teams — RFQ desk first; every row on Slide 1 tomorrow  

*Messy documents in → clean, reviewed data out*
